# KF-21 보라매 비행 전투 시뮬레이션 UI/UX 전면 리뉴얼

## 1. 프로젝트 목표

현재 개발 중인 KF-21 보라매 기반 비행 전투 시뮬레이션 프로그램의 전체 UI/UX를 전문적인 상용 비행 시뮬레이터 수준으로 개선한다.

단순히 색상, 폰트, 버튼 모양만 변경하는 것이 아니라 로그인, 메인 메뉴, 미션 선택, 미션 브리핑, 비행 HUD, 설정, 일시정지, 결과 화면 등 전체 사용자 경험을 일관된 디자인 시스템으로 재구성한다.

최종 목표는 고급스럽고 전문적이면서도 과도하게 화려하지 않은 밀리터리 시뮬레이터 UI를 구현하는 것이다.

## 2. 디자인 콘셉트

다음 디자인 키워드를 기준으로 작업한다.

- Premium Military Flight Simulator
- Modern Aviation Interface
- Clean, Minimal, Professional
- Dark Navy / Aviation Blue / Cyan
- Subtle Glassmorphism
- Precise and Restrained Motion Design

### 컬러 시스템

다음 값을 초기 디자인 기준으로 사용하되, 공통 설정에서 일괄 변경할 수 있도록 구성한다.

- Primary Background: #06111F
- Secondary Background: #0A1B2D
- Panel Background: #0B2035
- Primary Blue: #1677F8
- Accent Cyan: #46D7F2
- Primary Text: #F2F6FC
- Secondary Text: #91A6BC
- Border: #24435F
- Success: #36C995
- Warning: #F4B84A
- Error: #F05B68

전체 화면에 강한 네온 효과를 남발하지 않는다. 강조가 필요한 버튼, 선택 상태, 진행 표시 등에만 포인트 컬러를 사용한다.

### 디자인 원칙

1. 충분한 여백과 명확한 정보 계층을 유지한다.
2. 제목, 설명, 주요 액션 버튼의 시각적 우선순위를 명확하게 구분한다.
3. 패널과 버튼은 일관된 모서리, 간격, 테두리, 높이를 사용한다.
4. 반투명 패널은 배경과 구분이 확실해야 하며, 텍스트 가독성을 우선한다.
5. 과도한 글로우, 과한 블러, 불필요한 장식, 지속적인 깜빡임을 사용하지 않는다.
6. 실제 항공기 HUD와 일반 메뉴 UI의 디자인 목적을 구분한다.
7. 전체 UI는 동일한 제품의 일부처럼 일관성을 유지한다.

## 3. 작업 전 필수 프로젝트 분석

코드를 수정하기 전에 현재 Unity 프로젝트를 먼저 분석한다.

- Unity 버전 및 UI 구현 방식 확인
- UGUI, UI Toolkit 등 기존 UI 시스템 확인
- 로그인, 메인 메뉴, 설정, HUD 등 기존 화면과 관련 스크립트 파악
- Scene, Prefab, Canvas, Panel, Button의 연결 구조 파악
- 기존 로그인 인증, 씬 전환, 비행 제어, 입력 처리, 데이터 저장 로직 파악
- 기존 애니메이션, 폰트, 이미지, 아이콘, 공통 UI 컴포넌트 확인
- 현재 UI에서 개선해야 할 항목과 기존 기능에 미치는 영향 분석

분석 결과를 먼저 간단하게 보고한다.

기존 프로젝트가 UGUI 기반이라면 UGUI를 우선 활용하고, UI Toolkit 기반이라면 기존 시스템을 유지한다. 명확한 이유 없이 UI 시스템 전체를 교체하지 않는다.

기존 기능을 유지하면서 디자인과 상호작용을 개선하는 것이 최우선이다.

## 4. 전체 화면 디자인

다음 화면을 프로젝트에 실제로 존재하는지 확인한 뒤 적용한다. 존재하지 않는 화면은 임의로 완성된 기능처럼 만들지 말고, 필요한 경우 별도 제안한다.

### A. 로그인 화면

- 화면 전체를 활용하는 고품질 KF-21 비행 또는 격납고 배경
- 좌측 또는 좌측 중앙에 로그인 UI 배치
- KF-21 BORAMAE 로고와 FLIGHT COMBAT SIMULATION 서브타이틀
- 아이디 및 비밀번호 입력 필드
- 로그인 버튼과 게스트 입장 버튼
- 필요한 경우 로그인 상태 유지, 계정 관련 메뉴 제공
- 우측 상단에 설정 등 보조 메뉴 배치
- 하단에는 버전 정보 등 최소한의 정보 표시

배경 이미지는 입력 필드와 버튼의 가독성을 방해하지 않도록 어두운 그라데이션 오버레이를 적용한다.

최초 진입 시 배경, 로고, 로그인 패널이 순차적으로 자연스럽게 나타나도록 한다.

### B. 메인 메뉴

- KF-21 비행 장면을 활용한 메인 비주얼
- 좌측에 주요 메뉴를 세로로 배치
- 주요 메뉴: 비행 시작, 미션 선택, 훈련, 설정, 종료
- 우측 상단에 파일럿 프로필 등 기존 기능이 있다면 배치
- 선택된 메뉴는 색상, 좌측 표시선, 미세한 이동 효과로 구분

메뉴가 많아지더라도 복잡해 보이지 않도록 한다.

### C. 미션 선택 및 브리핑

- 미션 카드 또는 목록과 상세 정보 패널 구성
- 미션명, 설명, 목표, 난이도 등 실제 프로젝트에서 제공하는 정보만 표시
- 지형 또는 작전 지역 이미지가 있다면 활용
- 미션 시작 전 사용자가 필요한 정보를 명확히 확인할 수 있도록 구성
- 미션 시작 버튼은 가장 중요한 액션으로 강조

실제 데이터와 연결되지 않은 미션 정보나 작전 목표를 임의로 생성하지 않는다.

### D. 비행 HUD 및 전투 화면

비행 중 HUD는 일반 메뉴와 별도의 디자인 체계로 관리한다.

- 실제 비행 정보와 기존 계기 데이터를 유지한다.
- 기존 HUD의 기능과 위치 정보, 입력 처리를 훼손하지 않는다.
- 시야를 가리거나 비행 판단을 방해하는 장식을 추가하지 않는다.
- 표적, 비행 정보, 경고, 무장 정보 등의 시각적 우선순위를 구분한다.
- 비행 중 불필요한 페이드 효과나 화면 전체 애니메이션을 사용하지 않는다.
- 기존 HUD 정보의 의미와 데이터 바인딩을 임의로 변경하지 않는다.

### E. 설정 화면

- 그래픽, 사운드, 조작, 게임플레이 등 기존 설정을 카테고리별로 분리
- 좌측 카테고리 메뉴와 우측 설정 패널 구조를 우선 검토
- 슬라이더, 토글, 드롭다운의 디자인 통일
- 변경 및 취소 버튼 제공
- 기존 설정값 저장 및 적용 로직 유지

### F. 일시정지 화면

- 현재 비행 화면을 유지하고 그 위에 어두운 오버레이 적용
- 중앙에 간결한 패널 표시
- 계속하기, 설정, 미션 재시작, 메인 메뉴 버튼 배치
- 재시작이나 메인 메뉴 이동은 필요한 경우 확인 절차 적용

### G. 결과 화면

- 미션 성공 또는 실패를 명확하게 표시
- 기존 데이터가 존재하는 경우에만 비행 시간, 달성 목표, 점수 등의 결과 표시
- 재시도 및 메인 메뉴 이동 제공
- 결과가 나타날 때 패널과 결과 항목이 순차적으로 등장하도록 구현

### H. 로딩 및 종료 확인

- 기존 씬 로딩 구조와 연결
- 진행률을 알 수 있는 경우에만 실제 진행률 표시
- 진행률을 알 수 없다면 가짜 퍼센트를 표시하지 않는다.
- 종료 확인은 기존 종료 로직을 유지하면서 간결한 모달로 구현한다.

## 5. 버튼 및 UI 인터랙션

모든 버튼과 상호작용 가능한 UI는 공통 디자인 규칙을 사용한다.

### 버튼 상태

Normal:
- 기본 배경색과 얇은 테두리
- 명확한 텍스트 대비

Hover:
- 배경색을 약간 밝게 변경
- 테두리에 은은한 블루 강조
- 필요하면 1~2% 정도의 미세한 확대 또는 위치 변화
- 전환 시간은 약 0.12~0.18초

Pressed:
- 살짝 축소되는 피드백
- 배경색을 조금 더 진하게 변경
- 전환 시간은 약 0.06~0.10초

Selected:
- 현재 선택된 메뉴나 항목을 색상, 테두리, 표시선 등으로 명확하게 구분

Disabled:
- 명도와 채도를 낮춰 비활성 상태를 표현
- Hover 및 클릭 애니메이션을 적용하지 않음

Focused:
- 키보드 또는 게임패드 입력을 사용하는 경우 명확한 포커스 표시 제공

### 상호작용 규칙

- 버튼 클릭 시 시각적 피드백을 제공한다.
- 클릭 애니메이션이 실제 버튼 동작을 지연시키지 않도록 한다.
- 포인터 진입 및 이탈 시 애니메이션이 자연스럽게 연결되어야 한다.
- 빠른 연속 클릭에도 애니메이션 상태가 꼬이지 않아야 한다.
- 클릭 이벤트가 중복 실행되지 않도록 주의한다.
- 버튼이 아닌 장식용 UI에는 불필요한 Hover 효과를 적용하지 않는다.
- 입력 필드, 슬라이더, 토글, 드롭다운에도 각각 적절한 상태 표현을 적용한다.

## 6. Fade In / Fade Out 및 화면 전환

공통 전환 시스템을 구현한다.

- 최초 화면 진입: 배경 Fade In → 로고 → 주요 패널 순차 등장
- 패널 등장: CanvasGroup Alpha와 필요한 경우 미세한 이동을 조합
- 모달 열기: 배경 오버레이 Fade In → 모달 등장
- 모달 닫기: 모달 Fade Out → 배경 오버레이 제거
- 탭 변경: 기존 패널 Fade Out → 새 패널 Fade In
- 메인 메뉴 진입: 배경과 메뉴를 자연스럽게 전환
- 로딩 화면: 실제 씬 전환 흐름과 연동

초기 권장값:
- 버튼 Hover: 0.12~0.18초
- 클릭 피드백: 0.06~0.10초
- 작은 패널 전환: 0.18~0.25초
- 일반 화면 전환: 0.25~0.40초
- 배경 및 로고 등장: 0.40~0.70초

위 값은 초기 기준이며 실제 사용감에 따라 조정한다.

애니메이션은 필요할 때만 사용하고, 모든 요소가 동시에 움직이거나 순차 등장 시간이 지나치게 길어지지 않도록 한다.

페이드 중 입력 차단 여부, Raycast 차단, 전환 도중 중복 실행, 비활성화된 오브젝트의 상태 복원도 처리한다.

## 7. 공통 UI 아키텍처

프로젝트 구조에 적합하다면 다음과 같은 공통 컴포넌트를 구성한다.

- UITheme: 색상, 폰트, 간격, 모서리 등 디자인 토큰 관리
- UIButton: 공통 버튼 상태 및 애니메이션
- UITransition: Fade In/Out과 패널 전환
- UIModal: 확인, 취소, 경고 등 공통 모달
- UITab: 탭 전환 및 선택 상태
- UISettingsControl: 슬라이더, 토글, 드롭다운 등 공통 설정 컨트롤

위 클래스명을 무조건 그대로 생성할 필요는 없다. 기존 프로젝트에 유사한 시스템이 있으면 이를 재사용하거나 개선한다.

공통 컴포넌트는 중복 코드를 줄이고 화면 간 일관성을 유지하는 목적으로 사용한다.

기존 로그인 인증, 씬 전환, 게임 상태, 비행 제어 등의 로직과 디자인 표현을 분리한다.

불필요한 싱글턴, 과도한 추상화, 대규모 프레임워크 도입은 피한다.

## 8. 해상도 및 레이아웃

- 현재 프로젝트에서 사용하는 해상도와 화면 비율을 조사한다.
- 1920×1080을 기준으로 디자인하되, 실제 타깃 기기에서 기존에 지원하는 해상도와 화면 비율을 유지한다.
- Anchor, Canvas Scaler, Layout Group 등을 기존 구조에 맞게 사용한다.
- 고정 좌표만으로 모든 UI를 구성하지 않는다.
- 긴 텍스트, 작은 화면, 해상도 변경에서도 레이아웃이 깨지지 않도록 한다.
- 비행 HUD의 핵심 요소는 기존 의도된 위치와 크기를 유지한다.

## 9. 구현 및 작업 순서

다음 순서를 반드시 지킨다.

1단계: 프로젝트 구조와 기존 화면 분석

2단계: 디자인 시스템 및 공통 UI 컴포넌트 설계

3단계: 로그인 화면과 메인 메뉴 우선 적용

4단계: 버튼 상태, Hover, Click, Fade 전환 구현

5단계: 설정, 모달, 일시정지, 결과 화면 적용

6단계: 미션 브리핑과 기존 비행 HUD의 시각적 개선

7단계: 해상도, 입력, 씬 전환, 기능 회귀 테스트

각 단계가 끝날 때 다음 내용을 보고한다.

- 수정 및 추가한 파일
- 변경한 화면과 컴포넌트
- 기존 기능에 미치는 영향
- Unity Editor에서 확인할 테스트 항목
- 아직 구현되지 않았거나 추가 확인이 필요한 항목

가능한 경우 각 단계별로 Unity에서 바로 확인할 수 있는 상태까지 구현한다.

## 10. 작업 시 절대 준수할 사항

- 기존 프로젝트를 먼저 분석하고 수정한다.
- 요청하지 않은 게임 로직과 비행 물리 로직을 변경하지 않는다.
- 기존 로그인, 데이터 저장, 네트워크, 입력, 씬 전환 기능을 임의로 제거하지 않는다.
- 기존 오브젝트와 컴포넌트 참조가 끊어지지 않도록 한다.
- 사용하지 않는 기존 코드를 임의로 삭제하지 않는다.
- 기존 에셋을 우선 재사용하고, 없는 에셋은 대체 방안을 제안한다.
- 실제 파일로 존재하지 않는 이미지, 폰트, 아이콘을 있다고 가정하지 않는다.
- 외부 패키지나 에셋을 임의로 설치하지 않는다.
- 프로젝트 전체를 한 번에 재작성하지 않는다.
- 수정 후 컴파일 오류, Missing Reference, NullReferenceException, 입력 충돌 가능성을 점검한다.
- 실제 Unity 실행 검증이 불가능했다면 검증했다고 보고하지 않는다.

## 11. 최종 완료 기준

최종적으로 다음 조건을 만족해야 한다.

- 모든 화면이 동일한 디자인 언어를 사용한다.
- 버튼과 설정 컨트롤의 상태 표현이 통일되어 있다.
- Hover, Click, Fade In/Out이 자연스럽고 과하지 않다.
- 화면 전환 중 입력 충돌이나 중복 실행이 발생하지 않는다.
- 기존 로그인 및 게임 기능이 유지된다.
- 기존 비행 HUD의 정보 전달과 조작성이 훼손되지 않는다.
- 주요 해상도에서 UI가 깨지지 않는다.
- 공통 스타일을 한곳에서 관리할 수 있다.

우선 현재 프로젝트를 분석하고, 개선 계획을 제시한 다음 로그인 화면과 메인 메뉴부터 구현하라. 전체 프로젝트를 무작정 변경하지 말고, 각 단계에서 기존 기능 보존과 실제 동작 검증을 우선하라.

위 디자인 시안을 전체적인 시각적 기준으로 삼되, 실제 프로젝트의 기능과 구조에 맞게 구현하라.
